=== GPU evidence — why we claim the work really ran on the Adreno ===
assembled from two captures; the automated re-capture was cut short when we
ran the phone out of memory ourselves (see docs/CORRECTIONS.md §6)

--- [1] device capability line, as ggml prints it ---
ggml_vulkan: 0 = Adreno (TM) 830 (turnip Mesa driver) | uma: 1 | fp16: 1 | bf16: 0
              | fp4: 0 | warp size: 64 | shared memory: 32768
              | int dot: 0 | matrix cores: none

--- [2] what llama.cpp enumerates as a compute device ---
$ llama-cli --list-devices
Available devices:
  Vulkan0: Adreno (TM) 830 (8428 MiB, 5682 MiB free)

# NOTE: this list has exactly one entry, and it is the real GPU.
#       The system also ships lvp_icd (lavapipe = CPU software rasteriser).
#       If ggml had picked that, "Vulkan works" would be true and
#       "GPU is used" would be false.

--- [4] the process holds the Adreno driver node open ---
see proc-evidence.log:
  fd_kgsl_open=1     -> /dev/kgsl-3d0 (Qualcomm GPU driver node) is in the fd table
  maps_freedreno=3   -> libvulkan_freedreno.so is mapped
  maps_libvulkan=9

# /dev/kgsl-3d0 is crw-rw-rw-, so this is checkable without root.
# Nothing on a CPU-only path opens it.

--- [5] cross-check: CPU time collapses 33s -> 5s ---
see cpu-seconds.txt. Not explainable by anything other than the work moving
off the CPU.

--- [6] what we could NOT measure ---
GPU utilisation percentage. All six candidate sources are unreadable without root:
  /sys/kernel/debug/kgsl/kgsl-3d0/gpubusy              NOT READABLE
  /sys/kernel/debug/kgsl/kgsl-3d0/gpu_busy_percentage  NOT READABLE
  /sys/class/kgsl/kgsl-3d0/gpubusy                     NOT READABLE
  /proc/gpuinfo                                        NOT READABLE
  /proc/gpufreq/gpufreq_opp_dump                       NOT READABLE
  /sys/kernel/ged/hal/gpu_utilization                  NOT READABLE
No dumpsys, no root, no GPU entry under /proc or /sys/class.
We did not substitute a different number for it.
